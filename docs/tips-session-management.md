# 使用技巧：会话找回与命名

> 这不是配置项，而是**用熟 Pi 自带能力**的小技巧。解决"会话太多、标题乱、搜不到历史"的痛点。

## 痛点

- 会话一多，`/resume` 列表又长又乱。
- 默认会话名 = 你的**第一条消息**（比如"帮我看看这个报错"），没有自动总结，完全看不出这个会话聊了什么。
- 想继续以前某个会话，但靠标题根本认不出来，搜索也"搜不到"。

## 根因

Pi 的会话**不会自动起名字**：你不手动命名，它就是第一条消息的开头。所以"标题乱"是必然的——**需要你主动命名**。

## 解法一：给会话命名 `/name`

任何时刻都能改名：

```
/name <需求名或任务名> 修复
```

- 命名会话在 `/resume` 里更好认
- 启动时也能命名：`pi --name "Refactor auth module"`
- 用 `/session` 可以随时查看当前会话信息

**习惯建议**：一个需求/一个主题开新会话时，第一句就把名字起好（或马上 `/name`）。后期你想"找回来继续"全靠它。

## 解法二：找回会话 `/resume`（含搜索）

`/resume`（或启动时 `pi -r`）打开会话选择器。顶部会显示当前范围（Current Folder / All，`Tab` 切换）、名称过滤（All / Named）和排序模式。

**搜索语法**：

| 语法 | 作用 |
|---|---|
| 直接输入 | 模糊搜索（搜全部消息文本，不只是标题） |
| `re:<正则>` | 正则表达式搜索 |
| `"短语"` | 精确短语搜索 |

**排序模式**（`Ctrl+S` 循环切换，选择器顶部实时显示当前模式）：

| 模式 | 说明 |
|---|---|
| **Threaded**（默认） | 线程树状视图：`/fork`、`/clone` 出的子会话按血缘挂在父会话下（`├─`/`└─` 缀），根节点按最近活跃排序 |
| **Recent** | 纯列表，按最近修改时间倒序 |
| **Relevance** | 搜索时按相关度排序 |

**其他操作**：

| 操作 | 作用 |
|---|---|
| `Tab` | 切换范围：当前目录 / 全部目录 |
| `Ctrl+N` | 只过滤显示**已命名**的会话（已命名的在列表中高亮显示） |
| `Ctrl+P` | 切换路径显示 |
| `Ctrl+R` | 直接重命名 |
| `Ctrl+D` / `Ctrl+Backspace` | 删除（确认后；装了 `trash` CLI 会进回收站） |

> 关键：**搜索能命中消息正文**，不只是标题。哪怕你只记得当时说过某句话，也能搜出来。

## 进阶：/tree / fork / clone

- `/tree`：查看当前会话的分支树，跳回任意历史节点继续（不新建文件）
- `/fork`：从某条历史消息 fork 出一个新会话
- `/clone`：把当前分支复制成新会话（改动前留备份很好用）
- `/compact`：把旧上下文总结压缩，缓解超长会话（见官方 Compaction 文档）

## 组合用法（推荐）

```
1. 每开一个主题 → /name 起个好名字（或用 pi --name 启动）
2. 忘了名字？ /resume 搜当时说过的关键句
3. 想回到岔路口 → /tree 跳回去重试
4. 改到一半怕改坏 → /clone 备份一份再继续
```
