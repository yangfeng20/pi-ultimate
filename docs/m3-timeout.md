# M3 命令超时规范

> 目标：任何命令都有超时上限，一条卡死的命令绝不拖垮整个会话。

## 痛点

- 没有显式 timeout，命令卡死 = 无限执行，会话被拖住。
- 超时设得过大（如 30000s）等于没设，失去保护意义。

## 规范（写入 AGENTS.md）

```
- bash 工具调用必须显式设置 timeout。
- grep 搜索类命令 ≤ 180s（3 分钟）。
- 其他命令 ≤ 300s（5 分钟）。
- 禁止省略 timeout；禁止传超大值。
- 预计超时 → 换替代方案（rg、缩小目录、分批查询、走日志/DB 工具），不得硬等。
```

## 为什么这样设

| 场景 | 上限 | 理由 |
|---|---|---|
| grep / rg 搜索 | 180s | 搜索是高频操作，卡住说明索引/目录有问题，应换工具 |
| 一般命令 | 300s | 编译、部署等长任务的上限，超过基本是卡死 |
| 超时后 | 换方案 | 硬等没有意义，改为更小的范围或专用工具 |

- AGENTS.md 中已含 `timeout` 关键词
- 故意跑一条超时命令，确认会被中断而不是无限挂起
